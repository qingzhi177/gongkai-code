接下来要做 需求3.md 里的内容：

修复1：L1 提取视角改为 AI 第一人称
文件：services/memory-service/extract_l1.py
问题：L1 索引没有明确视角，LLM 看到记忆时分不清是用户说的还是 AI 说的。
修改 EXTRACT_PROMPT，在核心规则的开头加上视角说明：
你正在为一个 AI 整理它的记忆。
对话中 [我] 是这个 AI，[你] 是和它对话的用户（她/用户的名字）。
请从 AI 的第一人称视角记录，让主语清晰：•"她说..."/"她喜欢..." → 明确是用户的内容•"我觉得..."/"我感到..." → 明确是 AI 的感受•"我们一起..." → 共同经历
不要写没有主语的句子（如"喜欢喝奶茶" → 谁喜欢？）
同时保留现有的情感类/信息类区分规则不变。

修复2：feel 来源区分
问题：AI 主动调 feel 工具记录的感受 和 从对话 L0 提取出的 feel 类型记忆混在一起。
方案：
- AI 主动调 feel 的记忆已经有 client="ai_self"，conv_id=""
- 在 Dashboard 的"感受"过滤里，加两个子按钮："AI自述" 和 "对话提取"
- 按 client 字段区分：client="ai_self" 是AI自述，其他是对话提取

修复3：Dashboard L1 列表只显示 100 条
文件：services/memory-service/main.py
找到 /l1/list 接口的 limit参数默认值，改成 500或 1000。
Dashboard 前端也可以加分页。

修复4：L1 内容手动编辑
在 Dashboard 的 L1 记忆列表里加一个"编辑"按钮。
点击后弹出文本框显示当前 content，可以修改后保存。
保存时：
1. 更新 SQLite 的 l1_memories.content
2. 重新生成 embedding 并更新 ChromaDB 对应向量
后端需要修改 PUT /l1/{memory_id} 接口，支持更新 content 字段，
并在 content 变化时重新调用 embedding API 更新向量。

修复5：L1 时间戳用 L0 原文时间
文件：services/memory-service/extract_l1.py
问题：L1 的 ts 字段是提取时间（datetime.now()），不是对话发生时间。
LLM 会把 L1 时间当作事件发生时间，导致时间认知错误。
修改 save_l1 函数：
- 用 source_msg_id 查 L0 消息的 ts 字段
- 把那个时间作为 L1 的 ts
- 如果查不到就 fallback 到 datetime.now()
同时在 ChromaDB 的 metadata 里也用 L0 的时间。

修复6：删除对话时联动清除 L1 + 向量
修改 DELETE /l0/conversation/{conv_id} 接口：
当前只做了：标记 L0 为 superseded
需要加上：
1. 查出该 conv_id 下所有 active 的 L1 的 id
2. 标记这些 L1 为 superseded
3. 从 ChromaDB 用 ids 列表删除对应向量

修复7：L0 版本切换时联动 L1
当网关 diff 检测到消息内容变化（版本切换）时：
1. 旧 L0 标记 superseded（已有）
2. 旧 L0 对应的 L1 也标记 superseded
3. 从 ChromaDB 删除旧 L1 的向量
4. 新 L0 的 extracted 设为 0，等下次 cron 重新提取

修复8：删除对话时同步清除 L1 和向量
当在 Dashboard 删除一个对话（DELETE /l0/conversation/{conv_id}）时：
1. 标记该 conv_id 下所有 L0 消息为 superseded（已有）
2. 同时标记该 conv_id 下所有 L1 记忆为 superseded
3. 从 ChromaDB 删除对应的向量（用 l1_{id} 作为 ID 删除）
