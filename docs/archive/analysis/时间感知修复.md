# 时间感知修复

## 问题1：LLM 时间线混淆

LLM 看记忆目录时没有"今天是哪天"的锚点，
会把历史记忆里描述的时间（如"过了十一天"）误解为当前状态。

## 问题2：会话间隔感知

LLM 不知道距上次对话过了多久，无法像朋友那样感知"好久不见"。

## 修复方案（两个一起做）

### A. memory service 加接口：GET /last_session

返回该conv_id 最近一条 L0 消息的时间戳（或全局最近一条）。

```python
@app.get("/last_session")
async def get_last_session(conv_id: Optional[str] = None):
    conn = sqlite3.connect(str(SQLITE_PATH))
    c = conn.cursor()
    if conv_id:
        row = c.execute(
            "SELECT ts FROM l0_messages WHERE conv_id=? AND status='active' ORDER BY ts DESC LIMIT 1",
            (conv_id,)
        ).fetchone()
    else:
        row = c.execute(
            "SELECT ts FROM l0_messages WHERE status='active' ORDER BY ts DESC LIMIT 1"
        ).fetchone()
    conn.close()
    return {"last_ts": row[0] if row else None}
```

### B. server.js 修改 getMemoryMenu 函数

在返回的 menu 头部加两个动态信息：
1. 当前时间（让 LLM 有时间锚点，解决问题1）
2. 会话间隔感知（解决问题2，阈值触发）

逻辑：

```javascript
async function getMemoryMenu(userMessage, convId) {
  // 1. 获取当前北京时间
  const now = new Date();
  now.setHours(now.getHours() + 8);
  const currentDateStr = now.toISOString().substring(0, 16).replace('T', ' ');
  
  // 2. 获取上次对话时间，计算间隔
  let sessionNote = '';
  try {
    const sessionRes = await axios.get(
      `${MEMORY_SERVICE_URL}/last_session?conv_id=${encodeURIComponent(convId || '')}`,
      { timeout: 3000 }
    );
    const lastTs = sessionRes.data.last_ts;
    if (lastTs) {
      const lastDate = new Date(lastTs + 'Z'); // UTC
      const gapMs = now.getTime() - lastDate.getTime();
      const gapHours = gapMs / (1000 * 60 * 60);
      if (gapHours >= 4 && gapHours < 24) {
        sessionNote = `距上次对话约${Math.round(gapHours)}小时`;
      } else if (gapHours >= 24 && gapHours < 24 * 7) {
        sessionNote = `距上次对话约${Math.round(gapHours / 24)}天`;
      } else if (gapHours >= 24 * 7) {
        sessionNote = `距上次对话约${Math.round(gapHours / 24)}天（有段时间没见）`;
      }
      // < 4小时：不注入，连续对话不打断
    }
  } catch (e) {
    // 查不到上次时间时静默跳过，不影响主流程
  }
  
  // 3. 构建记忆目录头部
  let header = `[当前时间：${currentDateStr}（北京时间）]`;
  if (sessionNote) {
    header += `\n[${sessionNote}]`;
  }
  
  // 4. 原有记忆检索逻辑...
  const res = await axios.post(`${MEMORY_SERVICE_URL}/search`, {
    query: userMessage, mode: "semantic", n: 8
  });
  const memories = res.data.memories || [];
  
  if (memories.length === 0) return header + '\n';
  
  let menu = header + '\n[相关记忆目录]\n';
  for (const m of memories) {
    const meta = m.metadata || {};
    const core = meta.is_core ? '⭐ ' : '- ';
    const date = meta.ts ? meta.ts.substring(0, 10) : '';
    const type = meta.event_type || '';
    const summary = m.l1_summary || m.content || '';
    menu += `${core}[${date} ${type}] ${summary.substring(0, 60)}\n`;
  }
  return menu;
}
```

注意：getMemoryMenu 调用处要传入 convId（从 resolveConvId(req) 获取）。

## 效果

LLM 每轮看到的注入内容变成：

（无间隔 or 间隔<4h）：
[当前时间：2026-07-28 22:30（北京时间）]
[相关记忆目录]
- [2026-07-05 event] 过了十一天，她回来了...

（间隔3天）：
[当前时间：2026-07-28 22:30（北京时间）]
[距上次对话约3天]
[相关记忆目录]
- [2026-07-05 event] 过了十一天，她回来了...

LLM 有了今天的日期锚点，就能正确理解历史记忆里的时间描述是过去的事件，
而不会误解为当前状态。

## 不影响 prompt caching

这两个动态信息（当前时间+ 会话间隔）都注入在 memoryMenu 里，
而 memoryMenu 已经是注入到 user 消息前面的动态部分，
system前缀（角色+画像+工具定义）保持不变，缓存命中不受影响。
