## 这次最重要的设计目标（原则，不是实现细节）

1. 默认活在当下，不要总被过去牵着走；只有在合适的时候，才自然想起一些过去的小细节。
2. Recall 不该是"关键词搜索"，而是"目的/意图驱动的联想"——即使模型不确定记忆是否存在，也应该能凭"隐约觉得聊过"去 recall，而不是必须先在目录里看到才敢搜。
3. Forget 的本质是**降低可见度**，不是删除。重要性可以一直很高，只是这段时间不该总出现在眼前；这和"硬删除记忆"是两套完全不同的机制，请不要合并处理。
4. L1 目录（memoryMenu）只是"提醒"，不是"答案本身"。目录之外可能还有很多没显示的记忆；不要让目录的缺席变成模型认定"以前没聊过"的证据。
5. `feel` 记录的是"AI 当下如何理解这一刻"，不是事件摘要；理想情况下未来可以修正（"我当时这么理解，后来发现不完全对"）。
6. LLM 负责"要不要回忆、为什么回忆"；Gateway 负责"怎么检索"；Memory Service 只负责"存、查、排序"，不掺判断——这样以后换模型（Claude/GPT/Gemini/Qwen）时 Memory Service 不用动。

## 希望你做的事（按顺序，每步之间等我确认）

### 第一步：只改 `recall` 的语义
把 `recall` 从"关键词搜索"变成"意图驱动的回忆"。具体要不要加 `purpose` / `uncertainty` / `allow_empty_query` 这类字段，请你先看现有的 `mode` / `event_type` 等参数能不能覆盖这个语义，如果加字段是最优解再加，不要为了加而加。同时请重写工具的 `description`，让它传达"可以凭感觉去找，不确定也可以搜"，而不是"目录不够用才查"。

### 第二步：调整 `memoryMenu` 的呈现方式
让它更轻、更少、更像"目录"而不是"内容压缩包"；在 prompt 里明确写清楚"这只是部分记忆的提醒，不代表所有相关记忆都已列出"。请检查现在的排序逻辑（相关性+is_core）是否会让模型把目录当成"用户世界的全部重要主题"，如果是，考虑要不要引入更轻量的呈现或限制条数。

### 第三步：给 Forget 补一个"降低可见度"的轻量机制
不要一开始做复杂的多字段衰减系统。请先分析现有的 `is_core` / `access_count` 能不能通过调整排序公式就达到效果，还是确实需要新增字段（比如 recency / fatigue）。这一步的目标只是"知道什么时候不该打扰"，不是"忘光"，也不是替换掉现有的硬删除/重提取功能——两者应该并存，服务不同的场景。

### 第四步：给 `feel` 补一个"可修正"的语义
不强求现在就实现自动触发的修正机制，但请说明如果要支持"以后回头发现理解有偏差"，现有的数据结构需要怎么调整（比如是否需要引用/覆盖旧的 feel 记录，还是新增一条并关联）。
